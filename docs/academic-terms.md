# การแยกข้อมูลตามภาคเรียน

บัญชีนักเรียน อีเมล รหัสผ่าน ข้อมูลใบหน้า ตัวอย่างใบหน้า และการผูกอีเมลยืนยันตัวตนใช้รหัสนักเรียนในระบบ (`students.id`) เดิมข้ามภาคเรียน ไม่ต้องสร้างบัญชีหรือยืนยันใบหน้าใหม่เมื่อเปลี่ยนเทอม

รายชื่อเข้าเรียนอยู่ใน `student_term_enrollments` แยกตามปีการศึกษา ภาคเรียน ห้อง และเลขที่ นักเรียนหนึ่งบัญชีอยู่ได้หนึ่งห้องต่อภาคเรียน ส่วนรายวิชาและประวัติการเข้าเรียนอ้างอิงภาคเรียนของรายวิชา การเปลี่ยนรายชื่อเทอม 2 ไม่แก้รายชื่อเทอม 1

## เตรียมฐานข้อมูล

เรียก `npm run db:academic-terms:check` เพื่อตรวจ และ `npm run db:academic-terms` เพื่อเพิ่มตาราง/ดัชนี การย้ายข้อมูลทำครั้งเดียวและบันทึกสถานะไว้:

- รายชื่อห้องเรียนเดิมย้ายเป็นเทอม 1 ของปีการศึกษาที่บันทึกไว้ในห้อง
- ประวัติการเข้าเรียนเดิมช่วยรักษาสมาชิกในภาคเรียนย้อนหลังที่มีหลักฐานอยู่แล้ว
- เทอม 2 ที่ยังไม่มีข้อมูลเริ่มด้วยรายชื่อว่าง ไม่มีการคัดลอกรายชื่อเทอม 1 โดยอัตโนมัติ
- รหัสวิชาซ้ำข้ามปีหรือเทอมได้ แต่ภายในปีและเทอมเดียวกันยังต้องไม่ซ้ำ
- คำร้องแก้ไขห้องหรือเลขที่เก็บภาคเรียนตอนยื่นคำร้องไว้ การอนุมัติหลังเปลี่ยนเทอมจึงแก้เฉพาะภาคเรียนเดิมของคำร้อง
- คำสั่งนี้ไม่ลบหรือสร้างบัญชีนักเรียนใหม่ และไม่เปลี่ยนข้อมูลอีเมลหรือใบหน้า

หลังเปลี่ยน Prisma schema ให้เรียก `npx prisma generate` ก่อน build ตามปกติ

## เปิดเทอมใหม่

เลือกปีการศึกษาและเทอมในหน้าจัดการนักเรียน แล้วเพิ่มผู้เรียนจากบัญชีเดิมหรือนำเข้ารายชื่อโดยใช้รหัสนักเรียน/อีเมลเดิม จากนั้นเพิ่มรายวิชาและตารางสอนของเทอมนั้น นักเรียนที่เข้ารายชื่อใหม่แล้วใช้ข้อมูลใบหน้าและอีเมลเดิมในการเช็คชื่อได้

## ตรวจสอบ

`node --test tests/academic-term-rules.test.mjs` ตรวจการเลือกเทอม ส่วน integration test ใช้ `RUN_ACADEMIC_TERM_INTEGRATION=1` ร่วมกับ `TEST_DATABASE_URL` (หรือ `DATABASE_URL`) และเรียก `node --test tests/academic-terms.integration.test.mjs` โดยทุกข้อมูลทดสอบอยู่ใน transaction ที่ rollback เสมอ
